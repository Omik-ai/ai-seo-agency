## Reporting a Vulnerability

We take security vulnerabilities seriously. If you discover a security issue, please report it responsibly.

### How to Report

1. **Do NOT open a public issue** — This could expose the vulnerability
2. **Email the maintainer directly** — Contact through GitHub or the project contact
3. **Include the following information**:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Any suggested fixes (optional)

### Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial Assessment**: Within 7 days
- **Fix Timeline**: Depends on severity (see below)

### Severity Classification

| Severity | Response Time | Fix Target |
|----------|---------------|------------|
| Critical | 24 hours      | 7 days     |
| High     | 48 hours      | 14 days    |
| Medium   | 7 days        | 30 days    |
| Low      | 30 days       | Next release|

## Security Best Practices

### For Users

1. **Keep your AI tool updated** — Use the latest version of Claude Code, Cursor, etc.
2. **Review generated content** — AI can make mistakes; always human-review outputs
3. **Protect API keys** — Never expose API keys in public repositories
4. **Validate external URLs** — Don't blindly trust URLs generated by agents

### For Contributors

1. **No secrets in code** — Use environment variables, never hardcode credentials
2. **Sanitize inputs** — Validate and sanitize all user inputs
3. **Log responsibly** — Never log sensitive information
4. **Review before commit** — Check for accidental secret exposure

## Known Security Considerations

### AI-Generated Content

- **Always human-review** AI-generated SEO content, meta tags, etc.
- **Verify claims** — AI may generate inaccurate statistics or claims
- **Check links** — Always verify external links work and are appropriate

### External API Calls

This project may interface with external APIs (Google Analytics, Search Console, etc.):
- **Never commit API keys** — Use environment variables
- **Rotate credentials** — Change API keys regularly
- **Use minimum permissions** — Grant only necessary access

### Data Privacy

- **Client data** — Never store client data in the repository
- **Working data** — Use `data/` directory, add to `.gitignore`
- **Logs** — Review logs before sharing externally

## Security Headers

When deploying any web interface:

```
Content-Security-Policy: default-src 'self'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Strict-Transport-Security: max-age=31536000
```

## Compliance

This project is designed for:
- **GDPR compliance** — No personal data processing by the agents
- **Client confidentiality** — Data stays in client-specific directories
- **Audit trails** — Full state management for accountability
